WEB · AUTOMATION · AI-DIRECTED DEVELOPMENT

nihiramusic.in

LiveOwn domain, HTTPS, updated regularly.

A website for my wife Nihira’s music: her original compositions, playback work, cover songs, concerts, news and awards, in one place.

Why
Nihira needed a better home for her music online. I also wanted a real project, with a result I cared about, to practise directing AI rather than just coding with it.
How
I took the role of project manager, with Claude as my development partner: clear goals, small steps, honest review of every change. The site itself is deliberately simple — static HTML, with all content in JSON data files that can be edited through forms instead of code.
Automation
Python scripts run on a schedule in GitHub Actions: new YouTube videos are picked up daily, concerts are synced from a calendar every few hours and move into past events once they are over, and every content change is validated before it is deployed.
What I learned
Directing AI is a different skill from coding with it. Most websites fail at maintenance, not at launch, so design for month six. And whoever ships it stays accountable for it — the essay goes into more detail.
  • Static HTML
  • JSON content
  • Python
  • GitHub Actions
  • GitHub Pages

CRICKET · DATA · PYTHON

CricketIQ

LivePublic web application.

A cricket analytics application built on ball-by-ball data, for exploring matches, players and performance.

Why
As a coach and performance analyst, I spend a lot of time with cricket data. CricketIQ is where that work meets software: an attempt to make match and player analysis quicker and more accessible.
How
Python for the data processing and analysis, with a Streamlit web interface so the results can be explored without writing code.
Where it stands
Live and in active development. Current work focuses on richer player-level data and on making the analysis accessible to AI tools.

  • Ball-by-ball data

WORKFLOW AUTOMATION · DOCUMENTS

VisaFlow

PrototypeBasic working version, not public.

A prototype for preparing visa applications from documents instead of retyping the same details by hand.

Why
Visa applications ask for the same personal details again and again, copied from passports and other documents. That is slow and easy to get wrong.
How
The prototype reads a passport and extracts its main fields into structured data.
Where it stands
Passport reading and field extraction work. The longer-term idea is a predictable, repeatable workflow from documents to a finished application.

PRODUCT EXPERIMENT · WEB

FamDeck

In progressPrivate for now.

A family dashboard: one shared place for the documents, travel plans, calendars and links a household needs.

Why
Family information tends to be spread across drives, calendars and folders. FamDeck brings it together in one place, for the whole family.
How
A React and TypeScript application built with Vite and Tailwind CSS. Navigation, sections and links are defined in JSON configuration files with validation, so adding content does not mean changing code. It is installable as a web app and deployed automatically through GitHub Actions.
Where it stands
The application shell and quick access to shared documents are in place; the remaining sections, from calendar to finance, are still to be built.
  • React
  • TypeScript
  • Vite
  • Tailwind CSS
  • PWA
